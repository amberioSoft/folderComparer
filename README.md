# Folder Diff

Порівняння двох папок як у git плюс передача папки на іншу машину через зашифровані PNG.

## Перший запуск на новій машині

```
git clone https://github.com/amberioSoft/imageZipper.git
cd imageZipper
dotnet publish -c Release -o dist
```

Ключа в репозиторії немає і бути не повинно. Покладіть свій `imgkeys.txt` поруч з `FolderDiff.csproj`, тоді csproj сам скопіює його у папку збірки, і програма підхопить ключ при запуску. Ключ для цієї машини і ключ для другої різні, це одна пара: перша машина пакує для другої, друга для першої.

Якщо ключа ще нема, відкрийте вкладку «Ключ» і натисніть «Створити пару». Один рядок лишіть собі, другий віддайте на другу машину. Генерувати нову пару, коли ключі вже розкладені, не треба: машини перестануть розуміти одна одну.


## Готовий exe

`dist\FolderDiff.exe` — один самодостатній файл на 59 МБ, .NET встановлювати не треба. Запускається подвійним кліком, папки вибираються кнопками «Огляд...» або перетягуванням у поля шляхів.

Перезбирати так:

```
dotnet publish -c Release -o dist
```

## Запуск з коду

```
dotnet run --project FolderDiff.csproj
dotnet run --project FolderDiff.csproj -- C:\path\old C:\path\new
```

Якщо передати два шляхи аргументами, порівняння стартує одразу. Останні шляхи й налаштування зберігаються у `%LocalAppData%\FolderDiff\settings.json` і підтягуються при наступному запуску.

## Що вміє

- **Статуси файлів**: `+` доданий, `−` видалений, `M` змінений, `=` однаковий. Порівняння за розміром і SHA-256, тому однакові файли не читаються двічі.
- **Діф двома колонками** з номерами рядків, підсвіткою рядків і підсвіткою окремих слів усередині змінених рядків. Є режим одного стовпця з `+`/`-` як у `git diff`.
- **Згортання незмінених рядків** з контекстом 1/3/5/10/25 рядків і заголовком на кшталт `@@ згорнуто рядків без змін: 16 @@`.
- **Навігація по змінах** кнопками або F7 / F8.
- **Оновлення** (Ctrl+R) перераховує все заново і зберігає вибраний файл. Повне порівняння — F5.
- **Слідкувати за змінами**: `FileSystemWatcher` на обидві папки з дебаунсом 800 мс, автоматично перезапускає порівняння.
- **Фільтри**: пошук за шляхом, фільтр за статусом, шаблони ігнорування через `;` (`bin`, `obj`, `*.user`, `sub/dir`).
- **Ігнорувати пробіли** та **ігнорувати кінці рядків** впливають і на статус файлу, і на діф, тому список і діф завжди узгоджені.
- Контекстні меню: відкрити файл, показати в Проводнику, копіювати шлях, копіювати діф у вигляді unified patch, копіювати рядок.
- Drag and drop папок у поля шляхів, подвійний клік відкриває файл, Esc скасовує порівняння.

## Структура

| Шар | Файли |
|---|---|
| Порівняння папок | `Services/FolderComparer.cs`, `Services/IgnoreMatcher.cs`, `Services/FileContentService.cs` |
| Побудова діфу | `Services/DiffService.cs` |

| Вікно і шаблони | `Views/MainWindow.xaml` |
| Рендер підсвітки, скрол, конвертери | `Infrastructure/` |

## Обмеження

- Текст читається як UTF-8 з визначенням BOM. Файли в cp1251 покажуть символи заміни.
- Порядковий діф вимкнений для файлів понад 20 МБ і для бінарних файлів, для них видно лише статус і розміри.
- Порожні папки не показуються, лише файли.
- Довгі рядки переносяться, а не прокручуються горизонтально.

## Передача папки картинками

Друга вкладка вбудовує функціонал консольного `imgconv`: папка перетворюється на набір PNG, де дані лежать у пікселях, а на другій машині з них збирається та сама папка. Код узятий як є з `C:\work\imageZipper\zipperASource\ImageConverter.cs` і лежить у `Vendor/ImageConverter.cs`. З копії вирізано лише консольний шар: класи `Program`, `PackCommand`, `UnpackCommand`, `CommandLine` і два методи `Paths.Ask`/`Paths.AskRequired`, які читали зі stdin. Решта 4770 рядків недоторкана, формати пікселів, заголовка і ключа не змінені, тому програма сумісна з консольною версією на другій машині.

Порівняння папок і передача працюють на тих самих двох шляхах: ліва папка «До» це база для різниці, права «Після» це те, що пакується.

### Ключ

Рівно як у консольній версії: файл `imgkeys.txt` лежить поруч з exe і підхоплюється сам при запуску. Вкладка «Ключ» показує стан, дає вкинути файл кнопкою, вставити рядок вручну, створити нову пару та, як необовʼязковий спосіб, використати папку з чотирма PEM-файлами з паролем.

### Що варто знати

- Упаковка і розпакування синхронні й довгі, тому виконуються у фоновому потоці, а прогрес їде в журнал. Скасування немає, кнопки заблоковані на час роботи.
- Пікова памʼять близько 1.1 ГБ на папці 258 МіБ, збірка x64.
- Помилки показуються текстом з винятку, він написаний для людини.
- Порядковий діф на вкладці «Різниця» і передача картинками використовують той самий список виключень, щоб не розходились.

## Розділювачі та виділення тексту

- Межу між панелями «До» і «Після» можна тягнути мишею. Смуга йде на всю висоту діфу, стартова позиція рівно посередині, а після першого перетягування позиція запамʼятовується у налаштуваннях.
- Межу списку файлів теж можна тягнути. Обидві ширини зберігаються між запусками у `DiffSplitWidth` і `FileListWidth`.
- Текст у діфі виділяється мишею і копіюється через Ctrl+C. Кожна половина рядка це `RichTextBox` у режимі лише читання, тому підсвітка змінених слів усередині рядка збереглася. Номери рядків лежать в окремій колонці і у виділення не потрапляють.
- Правий клік і далі меню дає копіювання цілого рядка або всього діфу файлу у вигляді unified patch.

## Список змінених файлів

Панель зліва зроблена як вікно Git Changes у Visual Studio: заголовок «Зміни (N)», під ним корінь із правою папкою, далі папки з жовтими іконками і файли. Ланцюжок папок з єдиною вкладеною папкою склеюється в один рядок, тобто `src\lib\configs` показується одним рядком, а не трьома. Статус файлу стоїть праворуч кольоровою літерою: `+` доданий, `−` видалений, `M` змінений.

Чекбокс «По папках» перемикає дерево і плоский список. Позиція запамʼятовується.

## Пробіли

Селектор «Пробіли» має три режими, як прапорці git:

| Режим | Відповідник у git | Що робить |
|---|---|---|
| Не ігнорувати | без прапорців | будь-яка різниця в пробілах це зміна |
| Кінцеві пробіли | `--ignore-space-at-eol` | пробіли в кінці рядка не рахуються |
| Усі пробіли | `-w` | відступи і пробіли всередині рядка не рахуються |

Режим впливає і на статус файлу в списку, і на діф, тому вони не розходяться. Текст у діфі завжди показується оригінальний, без нормалізації.

«Згортати незмінене» за замовчуванням вимкнено, тобто файл показується цілком.
